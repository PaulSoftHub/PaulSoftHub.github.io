01 — AI PE-OS

What is AI PE-OS?

AI PE-OS is a practical knowledge and working framework for developing, organizing, testing, maintaining, and improving AI-assisted workflows and prompt systems.

The purpose is not simply to write better prompts. It is to treat prompt engineering as a structured discipline that connects requirements, prompt development, version control, testing, deployment, documentation, and continuous improvement.

This knowledge hub documents the journey, methods, experiments, systems, lessons learned, and selected technical practices used while developing AI PE-OS.

02 — PROMPT ENGINEERING JOURNEY

From AI User to Prompt Engineer

The journey started with a simple objective: use AI more effectively in real professional work. Over time, it became clear that effective AI use requires more than asking good questions.

Prompts began to evolve from one-time instructions into structured, reusable assets. Requirements had to be defined, workflows had to be designed, outputs had to be reviewed, and successful approaches had to be documented and improved.

This led to a more systematic approach to prompt engineering — including Prompt Development Requests (PDRs), prompt specifications, runtime prompts, version control, testing, deployment, and continuous improvement.

AI PE-OS is the result of that evolution: a practical framework for turning AI-assisted work into structured, repeatable, maintainable systems.

03 — PROMPT DEVELOPMENT

From Requirement to Runtime Prompt

01

Requirement

Start with a clearly defined business, management, or workflow requirement. The objective is to understand what the AI system must accomplish before designing the prompt.

02

Prompt Development Request (PDR)

Convert the requirement into a structured Prompt Development Request that defines the purpose, scope, expected outcome, inputs, constraints, and important requirements.

03

Prompt Specification

Develop a detailed specification describing the intended behavior, workflow, output structure, rules, dependencies, and acceptance requirements of the prompt.

04

Runtime Prompt

Convert the approved specification into a production-ready runtime prompt designed for consistent execution within the intended AI workflow.

05

UAT

Test the runtime prompt against real work conditions. Identify gaps, incorrect outputs, missing requirements, and practical usability issues before considering it production-ready.

06

Production & Improvement

Once validated, maintain the prompt as a controlled production asset with versioning, documentation, deployment, verification, and continuous improvement.

04 — AI PE-OS ARCHITECTURE

From Prompt Development to Production

AI PE-OS uses a controlled workflow to develop, version, publish, verify, and execute production prompts.

01

VS Code

Create and edit prompt assets using structured Markdown files within the AI PE-OS repository.

02

GitHub Desktop

Review changes, create a commit, and push the approved prompt changes to GitHub.

03

GitHub

Maintain the controlled source version of production prompt files inside the repository.

04

GitHub Actions

Automatically detect production prompt changes and initiate the publishing workflow.

05

Google Apps Script

Receive the publishing request through HTTPS, validate the webhook secret, and publish or update the prompt in Google Drive.

06

Google Drive

Store the published production prompt in the Runtime Prompt Library used by the AI workflow.

07

Claude

Execute the approved runtime prompt from the production library within the intended workflow.

08

UAT & Continuous Improvement

Validate the prompt through actual work, identify gaps, improve the system, and maintain controlled future versions.
